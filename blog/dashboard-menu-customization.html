2026-05-20 Dashboard Customization 2.3.4

Customize the LiaisonOS Dashboard Menu

The Dashboard mode menu is now driven by a JSON config file. Hide modes you don't use, rename labels, build your own custom groups — all without recompiling, with live reload on save.

Sylvain Deguire (VA2OPS) · LiaisonOS 2.3.4

Why a JSON-driven menu

Every LiaisonOS operator runs a slightly different mix of modes. Some never touch ARDOP, some don't have a Mercury modem yet, some want Winlink VARA HF front-and-center while others live on JS8Call. Until 2.3.4, the dashboard menu was compiled into the binary — adapting it meant rebuilding from source.

In 2.3.4, the menu becomes data. A single JSON file describes every group, every mode card, every label and icon. The dashboard reads it at startup and watches the file for changes. Edit, save, the menu refreshes in place. No restart.

Your overrides file

LiaisonOS ships a default menu — the same one you see on a fresh install. Your customizations go into a separate overrides file in your home directory:

  • ~/.config/liaisonos/dashboard-menu.overrides.json — your customizations, survives upgrades

The dashboard merges this file with the built-in defaults on every reload. The file is created automatically on first launch with documentation and examples baked in. Open it to see every available option.

What you can change

The overrides file supports six kinds of edits. All are optional — keep what you don't need empty.

  • hide_modes — list of mode IDs to hide from the menu
  • hide_groups — entire group IDs to hide (e.g. drop the BBS group if you don't use it)
  • relabel — rename a mode (e.g. show "VarAC HF" instead of "VarAC (VARA Chat)")
  • add_to_group — add your own custom modes to an existing group
  • custom_groups — define entirely new groups, with their own title and items
  • group_order — reorder groups; unlisted groups follow in their default order

Hide a mode you don't use

The simplest customization: pull a mode you never run out of the menu. Open ~/.config/liaisonos/dashboard-menu.overrides.json and add:

{
  "hide_modes": ["winlink-ardop", "chat-chattervox-bt"]
}

Save. The ARDOP option vanishes from the Winlink picker, and Chattervox (BT) disappears from the Messaging group. The hidden mode still exists — you just don't see it in the menu. Remove the entry to bring it back.

Hide an entire group

If you never run a BBS, you can drop the whole BBS group:

{
  "hide_groups": ["bbs"]
}

The dashboard now has Messaging, APRS, and Tools — that's it.

Rename a mode

Use whatever label makes sense to you:

{
  "relabel": {
    "varac":   "VarAC HF",
    "js8call": "JS8"
  }
}

Add a custom group

Group your most-used modes into a "Favorites" section at the top of the menu:

{
  "custom_groups": [
    {
      "id": "favorites",
      "title_en": "MY FIELD STACK",
      "title_fr": "MA STATION TERRAIN",
      "icon": "⭐",
      "items": [
        { "type": "mode", "id": "varac",   "label": "VarAC",   "strip_icon": "💬" },
        { "type": "mode", "id": "js8call", "label": "JS8Call", "strip_icon": "📻" },
        { "type": "mode", "id": "winlink-vara-hf", "label": "Winlink VARA HF", "strip_icon": "📧" }
      ]
    }
  ],
  "group_order": ["favorites", "messaging", "aprs", "bbs", "tools"]
}

Your new MY FIELD STACK group appears first, with the three modes you actually use. Everything else stays in its default place after it.

Tip: The strip_icon field is an emoji shown in Strip Mode when the dashboard is collapsed. Pick whatever symbol speaks to you — 💬 for chat, 📧 for email, 🐺 for Chattervox, etc. The icon is rendered via Noto Color Emoji (ships with LiaisonOS).

Live reload

You don't have to restart QtDashboard. The dashboard watches the override file for changes — when you save in your editor, the menu rebuilds in roughly 200 ms. Try it: open the file in nano or your editor of choice, add "hide_modes": ["fldigi"], save, and watch the fldigi button disappear from the side panel.

This is how the future 2.3.5 visual menu editor (a Flask web app, same pattern as et-radio) will work: it writes to the overrides file, the dashboard live-reloads, you see the result instantly without ever touching JSON yourself.

Both UIs share one config

The same overrides file drives both the Desktop mode menu (sidebar) and the Touch mode card grid. Hide a mode here and it's hidden from your 7" tablet too. No per-UI duplication.

In Strip Mode — the 80 px collapsed sidebar new in 2.3.4 — your recent modes show their strip_icon emoji plus a short tag derived from the menu config.

Forward-compatible

If you upgrade LiaisonOS and a mode you'd hidden no longer exists (we removed it, you renamed it, whatever), the overrides file silently ignores that entry. Nothing breaks. The merge is forgiving.

Same goes for adding new modes: when LiaisonOS 2.3.5 ships and adds a mode to the Messaging group, you'll see it automatically — even if you have heavy customizations. The system default carries the update; your overrides only describe deltas.

Reset to defaults

If you want to wipe your customizations and go back to stock:

rm ~/.config/liaisonos/dashboard-menu.overrides.json

The dashboard recreates the file with the template content on next launch.

Coming next

In v2.3.5, the Menu Editor lands — a Flask web app that turns all of this into a point-and-click UI. Drag groups to reorder, toggle modes with a checkbox, pick icons from a grid. Behind the scenes it writes the same JSON file you can edit by hand today.

The JSON-driven menu is the foundation. Everything else builds on top.

Available in LiaisonOS 2.3.4 and later · Feature developed by VA2OPS
