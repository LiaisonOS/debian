QtPatWinlink — Pat Winlink, the LiaisonOS way

Pat Winlink reimagined as a fully native Qt application. Inbox, Outbox, embedded Pat Forms catalog, smart Abort/Disconnect handling, Touch Mode for field tablets — no browser tabs, no context switching.

Sylvain Deguire (VA2OPS) · LiaisonOS 2.3.3 · refined in 2.3.4

The browser problem

Pat Winlink is one of the best things to happen to amateur radio email in the past decade. It's fast, reliable, scriptable, and the team behind it ships consistently. There's just one thing — the standard way to use Pat is through a web browser tab. You open a terminal, run pat http, then open Firefox on localhost:8080, and click around in a web UI.

That works on a desktop. It also works, in a stretched-thin kind of way, on a tablet. But it's never quite right. You have three windows to manage. The browser doesn't know about your radio. Touch interactions are awkward. Context switching takes seconds you don't have in a field deployment. And on a 7" Toughpad screen, the browser's chrome alone eats 20% of your visible area.

LiaisonOS 2.3.3 introduced QtPatWinlink — Pat Winlink reimagined as a fully native Qt application. The web UI is gone. The browser is gone. What you get is a single app that looks and feels like it was built for amateur radio from day one.

Worth saying clearly: Pat itself is unchanged. We didn't fork Pat or compete with it. pat http still runs in the background, doing the heavy lifting. QtPatWinlink is a new client that talks to Pat's REST and WebSocket APIs — the same way the web UI does, but native.

One app, four mailboxes

The top of the window is a mailbox bar: Inbox, Outbox, Sent, Archive. Tap any tab, see a clean list of messages. Tap a message, it opens in a dialog with the body, headers, and attachments. Mark-as-read happens automatically when you read a message — no separate button to track.

Compose without the chrome

Composing a message in the web UI means a textarea inside a browser inside a window manager. QtPatWinlink's ComposeView is just the form — recipients, subject, body, attachments, send. Touch-friendly field heights, paste-from-clipboard works, no autocorrect surprises from the browser.

Attachments are added with a real file picker dialog (not a browser file input). Multiple files at once. Drag-and-drop works on desktop.

RMS connect — double-tap and go

This is where the native UI really pays off. The web UI's RMS list is a table — fine on desktop, terrible on touch. QtPatWinlink shows the same data as a large-row touchable table with three filter controls in a slim toolbar at the top: band, mode, distance. Hit the filter button to choose; the table updates in place.

Each row shows the callsign, frequency, distance, mode, and dial frequency. Double-tap a row to connect — no separate "Connect" button to find. The session console opens immediately and you're on your way.

Favourites are persistent. Star an RMS once, it sticks. The last-selected RMS is remembered too, so the next time you open the connect view, your most recent station is highlighted.

Session console — finally, a status line that makes sense

This is the screen you live on while a session is running. Top: a status label that says exactly what's happening — "Dialing FN35XB-10..." or "Connected — VA2BOB-10". Middle: a live progress bar with bytes-transferred during transfers. Bottom: a console log of every protocol event Pat reports — handshakes, file transfers, ACKs, retries.

Smart Abort / Disconnect

The single most-painful thing about VARA HF and Mercury sessions is the dance of trying to disconnect during a retry loop. VARA queues your disconnect, then ignores it because the modem is mid-handshake on the next retry. You wait. Nothing happens. You give up and kill the mode.

QtPatWinlink handles this for you. The button label changes contextually:

  • "Abort" — shown when Pat is still dialing. Sends /api/disconnect immediately, then again 2 seconds later, then 5 seconds after that. Catches VARA between retries.
  • "Disconnect" — shown when you're actually connected. Sends a single graceful disconnect.

And critically — Abort ends only the current connection attempt. The mode itself (pat-http, the modem) stays running. Pick another station, try again. No need to relaunch the whole stack.

Pat Forms — embedded in the app

Standard Pat Forms — Winlink's huge library of structured templates for emergency communications, position reports, ICS-213, ARES check-ins, etc. — normally lives in a separate browser tab pointed at localhost:8080/forms. Pick a form, fill it in HTML, the browser hands it back to Pat, Pat composes the message.

In QtPatWinlink, all of that happens inside the app. A "Forms" button opens the catalog picker. Pick a form, it renders in an embedded web view styled to match the rest of the UI. Fill it in, hit Submit, the message lands in your Outbox ready to send. No external browser. No clipboard juggling. No tabs.

The catalog is the full Pat Forms set — over 1,200 templates from FEMA, ARES, NTS, RACES, county SAR groups, etc. They're updated via Pat's normal formsUpdate mechanism; QtPatWinlink hosts a button for that too.

Touch Mode — field-ready

Like every UI-touching app in LiaisonOS, QtPatWinlink reads the Touch Mode flag from your user config. Set it once in QtDashboard and the whole app reflows:

  • Larger fonts everywhere (13 pt vs 10 pt on desktop)
  • Mailbox rows grow from 28 px to 48 px — comfortable finger targets
  • Buttons grow from compact to 48 px chunky touch buttons
  • Filter dropdowns become full-screen pickers
  • The action menu becomes a vertical stack of fat buttons instead of a system menu
  • Long-press selects text in message viewers (since you don't have a mouse)

The same binary serves both layouts. Operators who run a desktop Shack and a touch tablet in their vehicle get a consistent experience across both — just different sizing.

Mode chains — close the app, mode stops

In LiaisonOS 2.3.4, each Winlink mode launches QtPatWinlink as part of the mode chain. Close the app's window and the entire mode shuts down cleanly — Pat http, the modem, rigctld — all gone. No orphaned processes, no half-stuck "running" states, no need to manually find the Stop button on the dashboard.

If you just want to disconnect from your current station but keep the mode running for another attempt, that's the Disconnect button. If you're done for the session, just close the window. The supervisor handles the rest.

How to use it

  1. From QtDashboard, launch any Winlink mode (VARA HF, VARA FM, ARDOP, Mercury, Packet)
  2. QtPatWinlink opens automatically once Pat's HTTP server is ready
  3. Browse Inbox / Outbox / Sent / Archive from the top bar
  4. Compose a new message or pick a Pat Form
  5. Tap the Connect view, filter by band/mode/distance, double-tap an RMS to dial
  6. Watch the session console; Abort / Disconnect as needed
  7. Close the window when done — mode stops automatically

Coming next

QtPatWinlink is now the canonical Winlink client in LiaisonOS. Future work focuses on polish — better attachment previews, message search across all four mailboxes, possibly a quick-look mode for triaging long Inboxes during nets.

And as always, Pat itself stays in the loop. We're a client, not a fork. When Pat ships new features, QtPatWinlink picks them up through the same REST API the web UI uses.
