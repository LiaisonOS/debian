QtPatWinlink — Pat Winlink, version LiaisonOS

Pat Winlink réinventé en application Qt entièrement native. Inbox, Outbox, catalogue de formulaires Pat intégré, gestion intelligente Abort/Disconnect, mode Tactile pour tablettes de terrain — sans onglets de navigateur, sans changement de contexte.

Sylvain Deguire (VA2OPS) · LiaisonOS 2.3.3 · affiné en 2.3.4

Le problème du navigateur

Pat Winlink est l'une des meilleures choses arrivées au courrier radio amateur de la dernière décennie. C'est rapide, fiable, scriptable, et l'équipe derrière livre régulièrement. Il y a juste une chose — la façon standard d'utiliser Pat est via un onglet de navigateur. Vous ouvrez un terminal, lancez pat http, puis ouvrez Firefox sur localhost:8080, et cliquez dans une interface web.

Ça fonctionne sur un bureau. Ça fonctionne aussi, péniblement, sur une tablette. Mais ce n'est jamais tout à fait correct. Vous avez trois fenêtres à gérer. Le navigateur ne connaît pas votre radio. Les interactions tactiles sont gauches. Les changements de contexte prennent des secondes que vous n'avez pas en déploiement terrain. Et sur l'écran d'une Toughpad 7", le chrome du navigateur seul mange 20 % de votre surface visible.

LiaisonOS 2.3.3 a introduit QtPatWinlink — Pat Winlink réinventé en application Qt entièrement native. L'interface web a disparu. Le navigateur a disparu. Ce que vous obtenez est une seule application qui ressemble et se comporte comme si elle avait été conçue pour la radio amateur dès le premier jour.

Important à dire clairement : Pat lui-même n'est pas modifié. Nous n'avons pas forké Pat ni concurrencé avec lui. pat http tourne toujours en arrière-plan, faisant le gros du travail. QtPatWinlink est un nouveau client qui parle aux API REST et WebSocket de Pat — de la même façon que l'interface web le fait, mais en natif.

Une app, quatre boîtes

Le haut de la fenêtre est une barre de boîtes : Inbox, Outbox, Envoyés, Archive. Tapez n'importe quel onglet, voyez une liste propre de messages. Tapez un message, il s'ouvre dans une boîte de dialogue avec le corps, les en-têtes et les pièces jointes. Le marquage-comme-lu se fait automatiquement quand vous lisez un message — pas de bouton séparé à gérer.

📥
Inbox
Messages non lus en gras, indicateur de pièce jointe, triable par date/expéditeur/sujet
📤
Outbox
Messages en attente avec taille et RMS cible affichés
✉️
Envoyés
Confirmations de livraison et horodatages
📁
Archive
Stockage long terme avec mêmes vue et recherche que l'Inbox

Composer sans le chrome

Composer un message dans l'interface web signifie un textarea dans un navigateur dans un gestionnaire de fenêtres. La vue Compose de QtPatWinlink est juste le formulaire — destinataires, sujet, corps, pièces jointes, envoi. Hauteurs de champs adaptées au tactile, le coller depuis le presse-papiers fonctionne, pas de surprises d'auto-correction du navigateur.

Les pièces jointes sont ajoutées avec un vrai dialogue de sélection de fichier (pas un input file de navigateur). Plusieurs fichiers à la fois. Le glisser-déposer fonctionne sur bureau.

Connexion RMS — double-tap et c'est parti

C'est là que l'interface native paie vraiment. La liste RMS de l'interface web est une table — correcte sur bureau, terrible sur tactile. QtPatWinlink affiche les mêmes données comme une table tactile à grandes lignes avec trois contrôles de filtre dans une barre d'outils mince en haut : bande, mode, distance. Appuyez sur le bouton de filtre pour choisir ; la table se met à jour sur place.

Chaque ligne affiche l'indicatif, la fréquence, la distance, le mode et la fréquence d'accord. Double-tapez une ligne pour vous connecter — pas de bouton « Connecter » séparé à trouver. La console de session s'ouvre immédiatement et vous voilà parti.

Les favoris sont persistants. Mettez une étoile sur un RMS une fois, ça reste. Le dernier RMS sélectionné est également mémorisé, donc la prochaine fois que vous ouvrez la vue Connect, votre station la plus récente est mise en évidence.

Console de session — enfin, une ligne d'état qui a du sens

C'est l'écran sur lequel vous vivez pendant qu'une session tourne. En haut : une étiquette d'état qui dit exactement ce qui se passe — « Dialing FN35XB-10... » ou « Connected — VA2BOB-10 ». Au milieu : une barre de progression en direct avec les octets transférés pendant les transferts. En bas : un journal console de chaque événement de protocole que Pat rapporte — handshakes, transferts de fichiers, ACKs, reprises.

Abort / Disconnect intelligent

La chose la plus douloureuse à propos des sessions VARA HF et Mercury est la danse pour essayer de se déconnecter pendant une boucle de reprise. VARA met votre déconnexion en file d'attente, puis l'ignore parce que le modem est au milieu d'un handshake sur la reprise suivante. Vous attendez. Rien ne se passe. Vous abandonnez et tuez le mode.

QtPatWinlink gère ça pour vous. L'étiquette du bouton change selon le contexte :

  • « Abort » — affiché quand Pat compose encore. Envoie /api/disconnect immédiatement, puis encore 2 secondes plus tard, puis 5 secondes après ça. Attrape VARA entre les reprises.
  • « Disconnect » — affiché quand vous êtes réellement connecté. Envoie une seule déconnexion gracieuse.

Et de manière critique — Abort termine seulement la tentative de connexion en cours. Le mode lui-même (pat-http, le modem) continue de tourner. Choisissez une autre station, réessayez. Pas besoin de relancer toute la pile.

Formulaires Pat — intégrés à l'application

Les formulaires Pat standards — la grande bibliothèque de modèles structurés de Winlink pour communications d'urgence, rapports de position, ICS-213, présences ARES, etc. — vivent normalement dans un onglet de navigateur séparé pointé vers localhost:8080/forms. Choisissez un formulaire, remplissez-le en HTML, le navigateur le rend à Pat, Pat compose le message.

Dans QtPatWinlink, tout ça se passe à l'intérieur de l'application. Un bouton « Forms » ouvre le sélecteur de catalogue. Choisissez un formulaire, il s'affiche dans une vue web intégrée stylisée pour correspondre au reste de l'interface. Remplissez-le, appuyez sur Submit, le message atterrit dans votre Outbox prêt à envoyer. Sans navigateur externe. Sans jonglerie avec le presse-papiers. Sans onglets.

Le catalogue est l'ensemble complet des formulaires Pat — plus de 1 200 modèles de la FEMA, ARES, NTS, RACES, groupes SAR de comté, etc. Ils sont mis à jour via le mécanisme formsUpdate normal de Pat ; QtPatWinlink héberge un bouton pour ça aussi.

Mode Tactile — prêt pour le terrain

Comme chaque app touchant l'UI dans LiaisonOS, QtPatWinlink lit le drapeau Mode Tactile depuis votre config utilisateur. Réglez-le une fois dans QtDashboard et toute l'app se réorganise :

  • Polices plus grandes partout (13 pt vs 10 pt sur bureau)
  • Les lignes de boîtes passent de 28 px à 48 px — cibles tactiles confortables
  • Les boutons passent de compacts à 48 px épais et tactiles
  • Les listes déroulantes de filtres deviennent des sélecteurs plein écran
  • Le menu d'actions devient une pile verticale de gros boutons au lieu d'un menu système
  • L'appui long sélectionne le texte dans les visualiseurs de messages (puisque vous n'avez pas de souris)

Le même binaire sert les deux dispositions. Les opérateurs qui utilisent un Shack bureau et une tablette tactile dans leur véhicule obtiennent une expérience cohérente sur les deux — juste un dimensionnement différent.

Chaînes de modes — fermez l'app, le mode s'arrête

Dans LiaisonOS 2.3.4, chaque mode Winlink lance QtPatWinlink comme partie de la chaîne de mode. Fermez la fenêtre de l'app et tout le mode s'arrête proprement — Pat http, le modem, rigctld — tout disparaît. Pas de processus orphelins, pas d'états « en cours » à moitié bloqués, pas besoin de trouver manuellement le bouton Stop sur le tableau de bord.

Si vous voulez juste vous déconnecter de votre station actuelle mais garder le mode en cours pour une autre tentative, c'est le bouton Disconnect. Si vous avez terminé pour la session, fermez simplement la fenêtre. Le superviseur s'occupe du reste.

Comment l'utiliser

  1. Depuis QtDashboard, lancez n'importe quel mode Winlink (VARA HF, VARA FM, ARDOP, Mercury, Packet)
  2. QtPatWinlink s'ouvre automatiquement une fois le serveur HTTP de Pat prêt
  3. Naviguez Inbox / Outbox / Envoyés / Archive depuis la barre du haut
  4. Composez un nouveau message ou choisissez un formulaire Pat
  5. Tapez la vue Connect, filtrez par bande/mode/distance, double-tapez un RMS pour composer
  6. Surveillez la console de session ; Abort / Disconnect au besoin
  7. Fermez la fenêtre quand terminé — le mode s'arrête automatiquement

À venir ensuite

QtPatWinlink est maintenant le client Winlink canonique dans LiaisonOS. Le travail futur se concentre sur le polissage — meilleurs aperçus de pièces jointes, recherche de messages dans les quatre boîtes, possiblement un mode aperçu rapide pour trier les Inbox longues pendant les nets.

Et comme toujours, Pat lui-même reste dans la boucle. Nous sommes un client, pas un fork. Quand Pat livre de nouvelles fonctionnalités, QtPatWinlink les récupère via la même API REST que l'interface web utilise.
